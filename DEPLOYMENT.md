# Детальне налаштування CarBook Web v2

Цей документ описує запуск із нуля. Стару базу Telegram-бота не використовуємо та не переносимо. GitHub Pages буде розміщувати лише вебінтерфейс, а всі облікові записи й автомобільні записи зберігатимуться у Supabase PostgreSQL.

---

## Частина 1. Створення Supabase Project

### 1. Увійти в Supabase

1. Відкрийте [https://supabase.com/dashboard](https://supabase.com/dashboard).
2. Увійдіть тим самим GitHub-акаунтом, через який уже реєструвалися.
3. Якщо ви бачите лише Organization або порожню панель без проєктів — це нормально. Реєстрація/вхід через GitHub створює обліковий запис Supabase, але не обов'язково створює окремий проєкт із базою.

### 2. Створити саме Project

1. Натисніть **New project**.
2. Виберіть свою Organization.
3. Назва проєкту: `CarBook` (або `carbook-main`).
4. Створіть надійний **Database Password**. Збережіть його у менеджері паролів. Цей пароль не потрібен у `config.js` і не повинен потрапляти в GitHub.
5. У полі Region виберіть найближчий доступний регіон у Європі.
6. Виберіть тариф відповідно до ваших потреб. Для початкового тестування достатньо початкового доступного тарифу; перевірте його ліміти перед активним використанням.
7. Натисніть **Create new project** та дочекайтеся завершення створення.

**Окрему базу даних вручну створювати не потрібно.** Під час створення Supabase Project автоматично розгортає PostgreSQL-базу. SQL-скрипт нижче створить у ній таблиці CarBook.

---

## Частина 2. Створення таблиць CarBook

1. Відкрийте створений проєкт `CarBook`.
2. У лівому меню відкрийте **SQL Editor**.
3. Натисніть **New query**.
4. На комп'ютері відкрийте файл `supabase-schema.sql` з архіву CarBook Web v2.
5. Скопіюйте весь його вміст — від першого коментаря до останнього `comment on table`.
6. Вставте текст у SQL Editor.
7. Натисніть **Run**.
8. Переконайтеся, що внизу з'явилося повідомлення про успішне виконання без червоних SQL-помилок.

Після виконання відкрийте **Table Editor**. Має бути видно шість таблиць:

| Таблиця | Призначення |
|---|---|
| `cars` | Автомобілі користувача |
| `fuel_entries` | Заправки |
| `expenses` | Інші витрати |
| `service_records` | Ремонти й технічне обслуговування |
| `reminders` | Нагадування |
| `notes` | Нотатки |

Скрипт також створює індекси, тригер `updated_at`, вмикає Row Level Security і додає політики доступу. Не вимикайте RLS для зручності тестування.

**Важливо:** цей SQL призначений для нового CarBook Project. Не запускайте його в старій production-базі Telegram-бота.

## Частина 3. Скопіювати Project URL і Publishable key

1. У Supabase відкрийте створений проєкт.
2. Натисніть **Connect** у верхній частині панелі або відкрийте **Project Settings → API Keys**.
3. Скопіюйте **Project URL**. Він має вигляд:

   `https://abcdefghijklmnop.supabase.co`

4. Скопіюйте **Publishable key**. У новому форматі він починається з `sb_publishable_`.
5. Якщо у вашій панелі поки показано лише старий ключ `anon` (довгий JWT, зазвичай починається з `eyJ...`), він також може використовуватися як клієнтський ключ. Перевагу надавайте Publishable key.

### Куди вставити ці значення

1. Відкрийте файл `config.js` у корені архіву.
2. Знайдіть цей фрагмент:

```js
window.CARBOOK_CONFIG = {
  supabaseUrl: "",
  publishableKey: ""
};
```

3. Вставте власні значення між лапками:

```js
window.CARBOOK_CONFIG = {
  supabaseUrl: "https://ВАШ_PROJECT_REF.supabase.co",
  publishableKey: "sb_publishable_ВАШ_КЛЮЧ"
};
```

4. Збережіть `config.js`.

### Який ключ НЕ МОЖНА вставляти

Ніколи не використовуйте у браузері:
- `sb_secret_...`;
- `service_role`;
- пароль PostgreSQL / Database Password.

Ці секрети мають привілейований доступ і не повинні бути в HTML, JavaScript, `config.js`, GitHub або в повідомленнях. Publishable key спеціально призначений для браузера; фактичний доступ до рядків обмежує RLS.

## Частина 4. Налаштувати реєстрацію та листи Supabase Auth

### 1. Увімкнути Email provider

1. У Supabase відкрийте **Authentication → Sign In / Providers** (назва підрозділу може трохи відрізнятися в поточній панелі).
2. Переконайтеся, що провайдер **Email** увімкнений.
3. Для звичайного використання рекомендовано залишити підтвердження електронної пошти увімкненим.
4. Якщо лист підтвердження не надходить, перевірте папку Spam та налаштування SMTP/ліміти відправлення. Для регулярного використання налаштуйте власний SMTP-провайдер у Supabase Auth.

### 2. Додати URL сайту

1. Відкрийте **Authentication → URL Configuration**.
2. У **Site URL** пізніше вставте адресу вашого GitHub Pages сайту. Наприклад:

   `https://ВАШ_GITHUB_ЛОГІН.github.io/carbook-web/`

3. У **Redirect URLs** додайте цю саму адресу та шаблон:

   `https://ВАШ_GITHUB_ЛОГІН.github.io/carbook-web/**`

4. Для локального тестування додайте:

   `http://localhost:8000/**`

5. Збережіть налаштування.

Якщо репозиторій називатиметься інакше, замініть `carbook-web` на фактичну назву репозиторію. Посилання повинно відповідати реальній адресі сайту, включно з кінцевим `/`.

## Частина 5. Завантажити вебзастосунок на GitHub

### 1. Створити репозиторій

1. Відкрийте [https://github.com](https://github.com).
2. Натисніть **New repository**.
3. Назва: `carbook-web`.
4. Для найпростішого запуску виберіть **Public**. GitHub Pages для приватних репозиторіїв залежить від тарифу GitHub.
5. Натисніть **Create repository**.

У репозиторії зберігатиметься код вебінтерфейсу. Таблиці, паролі користувачів та автомобільні записи у GitHub не зберігаються.

### 2. Завантажити файли

1. Розпакуйте `carbook_web_v2.zip` в окрему папку на комп'ютері.
2. Відкрийте цю папку з файлами проєкту.
3. Завантажте **вміст цієї папки** безпосередньо в корінь репозиторію, а не вкладену папку `carbook_web_v2`.
4. Перевірте, що на першому рівні репозиторію видно `index.html`, `app.js`, `core.mjs`, `styles.css`, `config.js`, `supabase-schema.sql` та `.nojekyll`.
5. Зробіть Commit changes.

`config.js` містить Project URL та Publishable key. Ці значення публічні за призначенням. У ньому не повинно бути жодних secret/service-role ключів або пароля бази.

### 3. Увімкнути GitHub Pages

1. У репозиторії відкрийте **Settings**.
2. У бічному меню виберіть **Pages**.
3. У **Build and deployment → Source** виберіть **Deploy from a branch**.
4. У Branch виберіть `main`.
5. У папці виберіть `/(root)`.
6. Натисніть **Save**.
7. Дочекайтеся завершення публікації. Адреса буде приблизно такою:

   `https://ВАШ_GITHUB_ЛОГІН.github.io/carbook-web/`

8. Відкрийте сайт. Якщо GitHub Pages ще не опублікував зміни, перевірте статус workflow у вкладці **Actions** та зачекайте завершення розгортання.

---

## Частина 6. Повернутися до Supabase та завершити URL Configuration

Після того як GitHub Pages опублікував сайт:

1. Скопіюйте точну адресу CarBook з браузера.
2. У Supabase відкрийте **Authentication → URL Configuration**.
3. Вставте адресу у **Site URL**.
4. Додайте цю адресу та її варіант із `/**` до **Redirect URLs**.
5. Збережіть.

Це потрібно для підтвердження email і відновлення пароля. Якщо URL не додано до allowlist, Supabase може відхилити redirect або повернути користувача не на ту сторінку.

---

## Частина 7. Перевірити роботу застосунку

Пройдіть послідовно:

1. Відкрийте GitHub Pages URL.
2. Створіть тестовий акаунт на окремій електронній пошті.
3. Якщо підтвердження email увімкнено — відкрийте лист і підтвердіть адресу.
4. Увійдіть у CarBook.
5. Додайте тестовий автомобіль, наприклад: `Toyota`, `Camry`, рік, тип пального, пробіг.
6. Додайте заправку з позначкою **«Заправлено повний бак»**.
7. Додайте наступну заправку з більшим пробігом, також позначивши повний бак. Після цього з'явиться розрахунок витрати пального за повним інтервалом.
8. Додайте витрату, сервісний запис, нагадування та нотатку.
9. Перевірте редагування й видалення тестового запису.
10. Вийдіть та увійдіть знову. Дані мають залишитися в базі.
11. Перевірте експорт CSV та JSON у розділі «Профіль та дані».

### Перевірка ізоляції користувачів

Це обов'язкова перевірка перед передачею застосунку іншим користувачам:

1. Створіть другий тестовий акаунт на іншій електронній пошті в іншому браузері або приватному вікні.
2. У першому акаунті створіть автомобіль і декілька записів.
3. Увійдіть другим акаунтом. Він не повинен бачити автомобіль або записи першого акаунта.
4. Створіть автомобіль у другому акаунті. Перший акаунт не повинен бачити його.

RLS політики в SQL-схемі є головним бар'єром ізоляції. Не вимикайте їх і не надавайте `anon` доступ до таблиць.

## Частина 8. Локальний запуск для перевірки

У папці проєкту відкрийте термінал і виконайте:

```bash
python -m http.server 8000
```

Відкрийте `http://localhost:8000`. Перед локальною перевіркою переконайтеся, що ця адреса додана в Supabase Redirect URLs. Не відкривайте `index.html` подвійним кліком через `file://` — ES modules і авторизаційні redirect-и потребують HTTP(S). На Windows можна запустити команду з PowerShell або термінала VS Code, попередньо перейшовши в цю папку.

---

## Частина 9. Локальні автоматизовані перевірки

Потрібен Node.js 20 або новіший. У Windows PowerShell виконайте з кореня папки проєкту:

```powershell
node --check app.js
node --check core.mjs
node --check sw.js
node --test tests/*.test.mjs
```

У Git Bash/macOS/Linux можна виконати коротку команду `./check.sh`.

## Частина 10. Резервні копії та відновлення

- Експорт JSON у CarBook зберігає автомобілі та записи користувача. Це зручна персональна копія даних, але не копія налаштувань Supabase, Auth-користувачів, SQL-політик чи всієї структури БД.
- Для повного відновлення бази використовуйте механізми Backups / Database backups, доступні для вашого тарифу Supabase, або окремий `pg_dump` із захищеного комп'ютера.
- Зберігайте Database Password окремо від репозиторію.
- Перевіряйте відновлення на окремому тестовому проєкті, а не на єдиній робочій базі.

## Частина 11. Що поки не входить у v2

- Автоматичні push/email/Telegram-сповіщення про нагадування. Наразі нагадування відображаються в інтерфейсі.
- PDF-звіт та публічне посилання для передачі історії автомобіля.
- Адміністративна панель і масові розсилки.
- Видалення акаунта з усіма даними. Це потребує окремої захищеної серверної функції, оскільки видалення Auth-користувача не можна безпечно робити з браузера через secret key.
- Офлайн-редагування та синхронізація. Service Worker кешує статичні файли, але зміни в базу потребують мережі.

Ці функції не позначені як готові, щоб не створювати враження, що вони вже працюють.
