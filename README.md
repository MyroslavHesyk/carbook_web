# CarBook Web v2

CarBook — адаптивний вебзастосунок для ведення персонального автомобільного журналу. Інтерфейс написаний на HTML, CSS та JavaScript без обов'язкового build-процесу. GitHub Pages розміщує статичні файли, Supabase забезпечує PostgreSQL, авторизацію та API.

## Можливості

- Реєстрація, вхід, вихід та відновлення пароля через Supabase Auth.
- Особистий гараж: створення, редагування та видалення автомобілів.
- Заправки: дата, пробіг, літри, сума, АЗС, тип пального, повний бак і примітка.
- Витрати: категорія, опис, сума та пробіг.
- Сервісна історія: виконані роботи, вартість і наступний інтервал ТО.
- Нагадування за датою та/або пробігом, позначення виконаних завдань.
- Нотатки, огляд, статистика, експорт CSV та повна копія JSON.
- Адаптивний інтерфейс для комп'ютера, планшета й телефона; PWA manifest.
- Row Level Security (RLS): записи доступні лише власнику автомобіля.

## Швидкий старт

1. Створіть новий Supabase Project.
2. У Supabase SQL Editor виконайте `supabase-schema.sql`.
3. У `config.js` вставте Project URL і Publishable key.
4. Завантажте вміст цієї папки в корінь GitHub-репозиторію.
5. Увімкніть GitHub Pages для гілки `main`, папка `/(root)`.
6. Додайте адресу опублікованого сайту до Supabase Auth URL Configuration.

Детальна інструкція з точними кроками: [`DEPLOYMENT.md`](./DEPLOYMENT.md).

## Локальна перевірка

Потрібен Python 3 або будь-який статичний HTTP-сервер. Не відкривайте `index.html` через `file://`, оскільки застосунок використовує ES modules.

```bash
python -m http.server 8000
```

Відкрийте `http://localhost:8000`.

## Тести

Потрібен Node.js 20 або новіший. Залежності npm не потрібні.

```bash
./check.sh
```

## Безпека

У браузері дозволено використовувати лише Supabase Publishable key (або legacy anon key). Ніколи не вставляйте `sb_secret_...` чи `service_role` у `config.js`, HTML, JavaScript або GitHub. Захист рядків реалізований політиками RLS у PostgreSQL.

`config.js` містить лише порожні значення до налаштування. Ключ Publishable призначений для клієнтського застосунку й не є паролем до бази даних.

## Межі поточної версії

- Автоматичні push, email або Telegram-сповіщення не реалізовані. Нагадування відображаються в застосунку.
- PDF-звіт, публічні посилання на сервісну історію, адміністрування/розсилки та видалення акаунта не реалізовані.
- Офлайн-створення та синхронізація записів не реалізовані. Service Worker кешує лише статичні ресурси.
- Середня витрата пального розраховується лише за інтервалами між заправками, позначеними як «повний бак».
- Попередня база Telegram-бота не переноситься. Supabase схема призначена для нового чистого проєкту.
